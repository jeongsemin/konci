# MediMate

**Honest, receipt-verified reviews of Korean hospitals and dermatology clinics, written by real patients for travelers.**
Available in English, 日本語, 中文 and 한국어.

한국을 여행하는 외국인을 위한 병원·피부과 후기 서비스입니다. 영수증으로 방문을 인증한 사용자만 후기를 쓸 수 있고,
영어 사용 여부·원장 직접 상담 같은 여행자가 궁금해하는 항목을 함께 남길 수 있습니다.

> **상태:** 핵심 기능이 구현되어 있고 단위 테스트 178개가 통과합니다. 실제 Supabase와 로컬 서버에서 주요 흐름을 확인했습니다.
> **배포 전**이며, 영수증 자동 판독(CLOVA OCR)과 네이버 검색은 키가 없어 쓰지 않습니다. 자세한 내용은 [현재 상태와 한계](#현재-상태와-한계)를 보세요.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 병원 검색·비교 | 심평원 공공데이터로 적재한 병원·의원 약 4만 곳을 이름·주소·지역으로 찾고, 평점·후기 수·영어·원장 상담·진료/시술로 걸러 최대 3곳을 비교합니다. 시술은 후기에 적힌 시술명을 기준으로 찾습니다 |
| 영수증 인증 | 영수증 사진을 올리면 OCR로 병원명·날짜·금액을 대조해 자동 인증하거나 관리자 검토로 넘깁니다 |
| 후기 | 별점, 방문 시기, 진료/시술, 후기(100~2,000자), 영어 지원·통역·원장 상담·가격 안내·강요 없음 항목 |
| 마이페이지 | 영수증 현황, 내 후기 삭제, 닉네임·국가·연령대·성별(비공개) 수정, 회원 탈퇴 |
| 신고 | 회원이 후기를 신고하면 관리자가 기각하거나, 후기를 숨기거나(되돌릴 수 있음), 작성자를 정지합니다 |
| 정보 수정 요청 | 전화번호·홈페이지·영문 병원명 등의 수정을 요청하고, 관리자가 승인하면 값이 바뀌고 잠겨서 재적재해도 유지됩니다 |
| 폐업·이전 | 회원이 제보하고 관리자가 승인하면 검색·홈(인기 병원·최근 후기)·사이트맵에서 빠지고 병원 페이지에 안내가 뜹니다. 새 후기는 받지 않고 기존 후기는 남습니다 |
| 병원 관리자 | 증빙을 낸 병원 관계자가 승인을 받으면 자기 병원의 일본어·중국어 이름과 진료시간을 수정 요청할 수 있습니다 |
| 건의사항 | 회원이 불편한 점을 남기면 **작성자와 관리자만** 보고, 관리자가 답변과 처리 상태를 남깁니다 |
| 회원 관리 | 가입자 목록·필터·일괄 정지/해제 |
| 약관·방침 | 이용약관과 개인정보처리방침 (4개 언어 초안) |
| 로그인 | Google 계정 또는 이메일 로그인 링크 (처음이면 계정이 자동으로 만들어집니다). 만 14세 이상·약관 동의 체크가 필요합니다 |
| 4개 언어 | `/en` `/ja` `/zh` `/ko`, 언어별 SEO 메타데이터 |

읽기·검색은 로그인 없이 가능하고, 영수증 업로드·후기·신고·건의부터 로그인이 필요합니다.
주요 경로: `/[lang]`, `/search`, `/hospitals/[id]`, `/reviews/[id]`, `/my`, `/feedback`, `/terms`, `/privacy`, 관리자용 `/admin`(`/members` `/reports` `/edits` `/managers`).

## 기술 스택

- **Next.js 16** (App Router, `proxy.ts`, Turbopack), React 19, TypeScript, Tailwind CSS 4
- **Supabase**: Auth(Google), Postgres + Row Level Security, 비공개 Storage
- 네이버 검색 API, 네이버 CLOVA OCR (둘 다 선택)
- 테스트: Node 내장 러너 (`node --test`)

## 시작하기

Node.js(개발은 v24, `.ts`를 직접 실행하는 최신 버전 필요)와 Supabase 프로젝트가 필요합니다.

```bash
npm install
cp .env.example .env.local   # 값을 채웁니다
npm run dev                  # http://localhost:3000
```

### 1. 환경 변수 (`.env.local`)

| 변수 | 필수 | 설명 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | Supabase 프로젝트 URL, 공개 키(RLS가 보호) |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | **서버 전용.** 영수증 처리, 관리자 화면 등에서 사용 |
| `HIRA_SERVICE_KEY` / `HIRA_DETAIL_SERVICE_KEY` | 적재 시 | 공공데이터포털 병원정보·상세정보 서비스 일반 인증키(Decoding). 적재 스크립트만 씁니다 |
| `NAVER_SEARCH_CLIENT_ID` / `NAVER_SEARCH_CLIENT_SECRET` | 선택 | 없으면 DB에 적재된 병원만 검색됩니다 |
| `CLOVA_OCR_INVOKE_URL` / `CLOVA_OCR_SECRET` | 선택 | 없으면 모든 영수증이 수동 검토로 넘어갑니다 |
| `NEXT_PUBLIC_SITE_URL` | 배포 시 | canonical·사이트맵 기준 주소 (기본 `http://localhost:3000`) |
| `NEXT_PUBLIC_CONTACT_EMAIL` | 배포 시 | 약관·방침에 표시되는 문의 연락처 (없으면 자리표시 주소) |

`.env.local`은 git에서 제외됩니다. **키를 저장소에 커밋하지 마세요.**

Supabase **SQL 편집기**에서 `supabase/migrations/`의 파일을 **번호 순서대로 한 번씩** 실행합니다. 같은 파일을 다시 실행해 "already exists"가 나오면 이미 적용된 것입니다.

| `0002_members` | 회원 정보(비공개)·정지 기록, 정지된 작성자의 후기 숨김, 관리자 회원 목록 함수 |
| `0003_reports` | 후기 숨김 컬럼, 신고 테이블 |
| `0004_hira` · `0005_search` | 심평원 컬럼, 검색용 뷰(`hospital_directory`) |
| `0006_edit_requests` | 정보 수정 요청, 변경 이력, 승인 함수 |
| `0007_hospital_managers` | 병원 관리자 신청·배정, 비공개 증빙 저장소, 일본어·중국어 이름 |
| `0008_treatments` | 숨긴·정지 후기를 통계에서 제외, 시술 필터용 컬럼 |
| `0009_closures` | 폐업·이전 처리 |
| `0010_account_deletion` | 회원 탈퇴, 지운 영수증의 **해시만** 보관(같은 사진 재사용 방지) |
| `0011_feedback` · `0012_feedback_private` | 건의사항 게시판, 작성자·관리자만 읽기 |
| `0013_email_login` | 이름이 없는 가입(이메일 로그인)의 닉네임을 `Member 1a2b`처럼 임의로 부여 (이메일 앞부분이 후기에 노출되지 않게) |

**영수증 정리:** `node --env-file=.env.local scripts/purge-receipts.ts [--dry-run]`은 후기가 없는 영수증을 30일 뒤 삭제합니다(심사 중은 제외). 배포 후 정기 실행에 등록해야 합니다.

### 3. 병원 데이터 적재 (심평원)

공공데이터포털에서 병원정보서비스(15001698)와 의료기관별상세정보서비스(15001699)를 신청하고 키를 넣은 뒤 실행합니다.

```bash
node --env-file=.env.local scripts/import-hira.ts --scope derm --dry-run   # 읽기만
node --env-file=.env.local scripts/import-hira.ts --scope all              # 상급종합·종합병원·병원·의원
node --env-file=.env.local scripts/import-hira.ts --details --limit 3000   # 피부과 전문의 수
```

- 덮어쓰기만 하고 **삭제하지 않아** 다시 실행해도 안전합니다. 수정 요청으로 잠근 항목과 폐업 상태는 유지됩니다.
- 요양병원·정신병원·치과·한방은 제외합니다. 개발 계정은 하루 1만 건 호출 한도가 있어 같은 명령을 다시 실행하면 이어서 받습니다.
- 공공누리 제1유형(출처 표시)이라 검색 결과에 출처를 표시합니다.

### 4. 로그인 (Google, 이메일)

1. Google Cloud Console에서 **웹 애플리케이션** OAuth 클라이언트를 만들고 리디렉션 URI에 `https://<project-ref>.supabase.co/auth/v1/callback`을 추가합니다.
2. Supabase → Authentication → Providers → **Google**을 켜고 클라이언트 ID·비밀번호를 입력합니다 (비밀번호는 앱 코드에 필요 없습니다).
3. Supabase → URL Configuration에서 Site URL과 Redirect URLs를 설정합니다 (로컬은 `http://localhost:3000`, `http://localhost:3000/**`).
4. 이메일 로그인은 Supabase의 **Email** 제공자(기본 켜짐)를 씁니다. 링크는 요청한 브라우저에서 열어야 하고, 기본 발송 한도가 작아서 실제 운영 전에는 별도 메일 서비스(SMTP) 연결이 필요합니다.

### 5. 관리자 지정

첫 관리자는 한 번 로그인한 뒤 SQL 편집기에서 지정합니다. 그다음부터는 `/admin`의 "관리자" 섹션에서 이메일로 추가·해제합니다 (마지막 관리자는 해제할 수 없습니다).

```sql
update public.profiles set is_admin = true
where id = (select id from auth.users where email = 'you@example.com');
```

## 영수증 인증 방식

`POST /api/receipts`가 처리합니다.

1. 로그인과 파일을 확인합니다. 파일 **첫 바이트**로 JPEG/PNG만 허용하고, 10MB·하루 10장으로 제한합니다.
2. SHA-256으로 **같은 사진의 재사용**을 막습니다 (지운 영수증도 해시로 기억합니다).
3. 비공개 버킷에 저장하고 CLOVA OCR로 병원명·결제일·금액을 읽습니다.
4. 병원명 유사도 ≥ 0.6, 결제일이 90일 이내이고 미래가 아님, 금액을 읽을 수 있음을 **모두** 만족하면 자동 인증, 아니면(OCR을 쓸 수 없는 경우 포함) 관리자 검토입니다.
5. 관리자는 `/admin`에서 원본과 OCR 결과를 비교해 승인하거나 사유와 함께 반려합니다.

OCR 결과는 신뢰하지 않는 입력으로 다루며, 이상한 값이 와도 업로드를 실패시키지 않고 수동 검토로 보냅니다. 영수증 한 장으로 후기는 한 번만 쓸 수 있습니다.
영수증은 후기와 함께 삭제되고, 후기가 없는 영수증은 30일 뒤 삭제됩니다. 탈퇴하면 후기·영수증·관리자 신청 서류가 즉시 삭제됩니다.

## 보안

- **RLS가 최종 방어선입니다.** 후기는 *본인의, 같은 병원의, 승인된 영수증*이 있어야 DB가 받아줍니다. 신고·건의·수정 요청도 본인 이름으로만 쓸 수 있고, 처리는 서버(서비스 키)만 합니다.
- **service role 키는 서버에만** 있고, `server-only`로 클라이언트 import를 빌드 단계에서 막습니다.
- **영수증과 증빙 서류는 비공개 버킷**에 있고 관리자에게도 5분짜리 임시 링크로만 보입니다.
- **서버 액션은 공개 엔드포인트로 취급**해 권한을 액션 안에서 다시 확인합니다.
- 국가·연령대·성별은 공개 테이블이 아니라 본인만 읽는 테이블에 둡니다.
- 정지와 숨김은 DB 정책으로 강제합니다. 로그인 후 이동 주소는 같은 사이트의 상대 경로만 허용합니다.
- 로그인·마이페이지·관리자·건의·후기 작성·검색 결과는 `noindex`입니다.
- `next`는 취약점이 알려진 16.4.0 대신 **16.4.2로 고정**했습니다 (`npm audit --omit=dev` 0건).

## 프로젝트 구조

```
src/
  app/[lang]/     # 언어별 페이지 (hospitals, reviews, search, my, feedback, admin, login, terms, privacy)
  app/api/        # 영수증 업로드, 병원 검색
  components/     # 헤더, 푸터 등 공용 UI
  i18n/           # 언어 설정, 사전(en/ja/zh/ko)
  lib/            # 도메인 로직 (대부분 순수 함수라 단위 테스트 가능), legal/ 은 약관·방침 문서
  proxy.ts        # 언어 라우팅 + Supabase 세션 갱신
supabase/migrations/   scripts/ (심평원 적재, 영수증 정리)   tests/
```

화면은 데이터 조회(`page.tsx`)와 표시(`*-view.tsx`)를 나눈 곳이 많아 가짜 데이터로도 확인할 수 있습니다.

## 현재 상태와 한계

**확인한 것** (실제 Supabase + 로컬 서버, 시험 데이터는 확인 후 모두 지움)
- 로그인 → 영수증 업로드 → 관리자 승인 → 후기 등록·삭제, 홈·병원 상세·마이페이지 표시와 집계
- 심평원 4만 곳 적재 후 검색·정렬·페이지, 재적재해도 수정·폐업 상태 유지
- 신고, 정보 수정 요청, 폐업·이전, 병원 관리자의 권한 범위, 시술 필터와 숨긴 후기 통계
- 영수증 30일 정리, 회원 탈퇴, 건의사항이 작성자와 관리자에게만 보이는지

**확인하지 못한 것**
- 일반 회원·병원 관리자 계정으로 하는 흐름 대부분 (관리자 계정 하나로만 시험했습니다). 탈퇴 버튼, 다른 회원의 후기 신고, 실제 정지·해제, 관리자 3명 정원, 건의 작성 화면이 그렇습니다
- 실제 CLOVA OCR 자동 승인과 네이버 검색 (키 없음). 규칙은 단위 테스트로만 확인했습니다
- 후기가 많을 때의 검색 속도와 정렬 (지금은 후기가 거의 없습니다)
- 배포 환경 (실제 도메인의 로그인 리디렉션, 사이트·연락처 주소, 메일 서비스(SMTP) 연결, 영수증 정리 스케줄 등록)

**한계**
- 병원 목록은 심평원 공공데이터 기준이며 폐업·이전과 시차가 있을 수 있습니다. 목록에서 사라진 병원을 자동으로 폐업 처리하지 않고, 회원 제보와 관리자 승인으로만 처리합니다
- 영문 병원명은 승인된 수정 요청으로만 생겨서 대부분 한글 이름뿐입니다. 후기 수가 같은 병원끼리는 피부과를 표방한 병원이 먼저, 그다음 가나다순입니다. 다만 표방 병원이 전체의 약 45%이고 가정의학과·성형외과도 많이 포함돼 있어 구분력은 약합니다
- 후기 수정·사진 첨부·병원 저장·임베드 지도는 없고, 병원의 홍보성 문구는 의료광고 규제 때문에 받지 않습니다
- 건의사항은 새 글 알림이 없어 관리자 화면에서 직접 확인해야 합니다
- 이용약관·개인정보처리방침은 **법률 검토를 받지 않은 초안**이며, 호스팅 업체와 국외 이전 항목은 배포 후 채워야 합니다. 만 14세 이상 확인은 로그인 화면의 체크박스(본인 확인)일 뿐 나이를 증명하지는 않습니다
- 이메일 로그인 메일은 Supabase 기본 발송을 쓰므로 시간당 한도가 작고, 제목·본문이 영문 기본 양식입니다
- Supabase 무료 플랜은 일주일쯤 쓰지 않으면 프로젝트가 일시중지됩니다

## 디자인 노트

Figma 시안은 가상의 병원·가격·후기를 담은 UI 콘셉트라, 실제 데이터와 영수증 인증을 다루는 이 서비스에 맞게 다르게 만들었습니다.
시술 가격·예약·광고·병원 사진은 데이터가 없어 제외했고, "최근 후기" 등은 가짜 대신 실제 DB 데이터로 채우며 없으면 섹션을 숨깁니다.
영수증 인증 단계, 영어·원장 상담 항목, 마이페이지, 관리자 화면은 시안에 없어 같은 디자인 시스템으로 추가했습니다.
디자인 토큰은 `src/app/globals.css`에 있고, 서체는 Inter와 Noto Sans KR/JP/SC입니다.
